# 마이페이지·공지 작성 메뉴

## 사용 방법

- 모든 로그인 사용자: 홈 상단 **마이페이지** → **이름 변경** → **이름 저장**. 주소는 `/auth/profile`이다.
- 저장하는 값은 본인의 표시 이름(`users.full_name`) 하나다. 로그인 아이디, 비밀번호, 소속, 계정 권한, 사용자 ID와 학습 기록은 변경하지 않는다. 홈 인사말과 계정 화면에는 저장한 이름을 사용한다.
- 이름은 앞뒤 공백을 제거한 1~100자다. 줄바꿈·제어 문자·보이지 않는 포맷 문자는 거절한다. 한글과 공백을 사용할 수 있다.
- 관리자: 홈 상단 **공지 작성**, 홈 공지 패널 **공지 작성 · PPT 업로드**, 마이페이지의 같은 버튼, 공지 목록의 같은 버튼으로 `/notices/new`에 들어간다. 제목·내용을 입력하고 PPT/PPTX 파일을 선택한 뒤 저장한다. 파일 1개·20MB 제한이며 기존 iframe 미리보기를 사용한다.
- 일반회원: 공지와 수업자료를 볼 수 있지만 작성·수정·삭제·업로드는 할 수 없다. 화면에 권한 안내를 표시한다. 이번 변경으로 일반회원의 권한을 올리지 않는다. 관리자가 필요한 사람은 기존 관리자에게 계정 권한을 확인받는다.

## 구현·보안

- `app/routes/auth.py`: 로그인 후 본인 이름 수정, 성공 시 303으로 다시 조회, 저장 오류 시 503 안내.
- `app/services/profile.py`: 이름 검증·단일 필드 저장·DB 오류 롤백.
- `app/services/profile_forms.py`: 마이페이지 전용 세션 CSRF 토큰과 상수 시간 비교. 공지의 CSRF 토큰과 분리한다.
- `app/templates/auth/profile.html`, `app/static/css/profile.css`: 정보 조회·이름 변경·권한별 공지 이동.
- `base.html`, `index.html`, `account-navigation.css`: 홈·하위 페이지의 진입 메뉴. 기존 학습 페이지 공통 CSS 파일은 수정하지 않는다.
- 요청의 `user_id`, `username`, `is_admin` 등은 이름 수정에 사용하지 않는다. DB 대상은 로그인한 사용자로만 결정한다. 폼 응답은 `private, no-store`, `nosniff`, `Vary: Cookie`를 적용한다. POST 본문은 8KB로 제한한다.
- 새 DB 테이블·칼럼·외부 패키지는 추가하지 않는다. 기존 `users.full_name` 칼럼을 사용한다. 기존 로그인·비밀번호 재설정 등 다른 인증 흐름은 이번 변경 대상이 아니다. 해당 기능 전체의 보안 감사를 통과했다는 의미는 아니다.

## 검사·배포·롤백

```bash
python -m unittest discover -s tests -q
```

프로필 테스트는 임시 SQLite에서 실제 템플릿·내비게이션을 검사한다. 관련 없는 학습 경로는 URL 생성용 대역으로 등록하며, 운영 초기화나 실제 DB를 호출하지 않는다. 로그인·CSRF·이름 검증·권한 위조·다른 사용자 수정 시도·XSS 출력·DB 실패 롤백·관리자 업로드 진입을 검사한다.

변경 전 운영 코드 백업: `/opt/vicabc-backups/profile-navigation-20261016-7pICHb/`. 새 서비스 모듈·라우트·템플릿·CSS를 함께 배포하고 앱 서비스를 재시작한다. Nginx 설정이나 DB 마이그레이션은 필요하지 않다. 실제 학생의 이름 저장·재조회·홈 반영과 관리자 PPT 업로드를 별도로 확인하고 검증용 변경은 되돌린다.

롤백은 위 백업의 기존 파일을 복구한 후 앱 서비스를 재시작한다. 새로 생긴 CSS/템플릿/서비스는 참조되지 않으면 남겨도 무방하다. 사용자가 이미 저장한 이름은 DB에 보존한다. 과거 DB로 덮어쓰거나 계정을 재생성하지 않는다.

## 운영 확인 — 2026-10-16

- 로컬 Python 3.13·운영 Python 3.10의 분리된 환경에서 전체 자동 검사 **87개**를 통과했다. 기존 첨부·iframe 70개와 새 마이페이지·권한/탐색 17개다.
- 운영 HTTPS 사이트에서 일반회원·관리자의 마이페이지를 확인했다. 실제 Chrome에서 이름을 저장하고 재조회·새로고침·홈 인사말 반영까지 확인했으며 기존 이름으로 복구했다. 로그인 아이디·소속·권한은 유지했다.
- 관리자 화면의 홈·마이페이지·공지 목록에 작성 경로가 표시됐다. 실제 PPTX 업로드·공지 저장·학생의 4장 iframe 열람과 원본 다운로드를 유지했다. 일반회원의 직접 작성 경로 접근은 403으로 차단됐다.
- PC 1440px와 모바일 390px 화면에서 마이페이지, 홈 메뉴, PPT 파일 선택 화면을 점검했다. 가로 넘침과 JavaScript 오류는 없었다.
- CSRF 오류·빈 이름은 거절됐다. 검증 공지·첨부·캐시는 삭제했고 기존 계정과 이름은 보존했다. 영어 사이트·Moodle 로그인 화면은 모두 HTTP 200이었다.
- 기존 공통 CSS 파일은 배포하지 않았다. 공통 템플릿의 기존 `v9` 스타일 캐시 버전은 보존하면서 새 메뉴와 별도 스타일만 추가했다. DB 마이그레이션·권한 승격은 없었다.
